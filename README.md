# 星课it-Web 协议详解与抓包实战
获课：xingkeit.top/18831/Web 协议详解与抓包实战


HTTPS 安全协议实战：TLS 握手、证书校验、加解密过程抓包拆解
HTTPS 的日常使用已经“无感”，但一旦出问题——证书报错、握手失败、抓包看不懂密文——没有底层认知就会束手无策。抓包是理解 TLS 最好的方式：把一次完整连接拆成明文可见的握手阶段和密文传输阶段，每个字段在解决什么问题就清楚了。下面按抓包顺序拆解。

一、抓包准备与整体框架

抓 HTTPS 包的关键是理解“哪些能看见、哪些看不见”。握手阶段的 ClientHello、ServerHello、Certificate、ServerKeyExchange 等消息是明文的，可以直接读；应用数据传输阶段全是密文，只有拿到会话密钥才能解密。Wireshark 配合浏览器导出 SSLKEYLOGFILE 可以解密，这是学习阶段最实用的手段。

一次 TLS 1.2 完整握手大致是：TCP 三次握手之后，客户端发 ClientHello，服务端回 ServerHello 加证书，双方交换密钥材料，各自算出会话密钥，然后 ChangeCipherSpec 之后全部加密。TLS 1.3 把往返压缩到一次，结构有变化但核心逻辑一致。

二、ClientHello：客户端亮出底牌

抓包看到的第一条 TLS 消息是 ClientHello，明文。里面几个关键字段。版本号声明客户端支持的最高 TLS 版本，实际协商取双方都支持的最高版。随机数（Client Random）是客户端生成的32字节随机值，后续密钥派生要用。会话 ID 用于会话复用，老连接恢复时省一次完整握手。密码套件列表是重点：客户端按优先级列出支持的加密组合，每个套件包含密钥交换算法、对称加密算法、消息认证算法，比如 ECDHE-RSA-AES128-GCM-SHA256 拆开就是密钥交换用 ECDHE、身份认证用 RSA、对称加密 AES128-GCM、摘要 SHA256。扩展字段里 SNI 携带目标域名，一个 IP 托管多站点时靠它选证书；ALPN 协商应用层协议，HTTP/2 就靠这个字段谈出来；supported_versions 在 TLS 1.3 里替代了版本号字段的作用。

三、ServerHello 与证书：服务端应答与身份证明

ServerHello 同样是明文。服务端从客户端列表里选定一个密码套件，生成 Server Random，回传会话 ID。接下来是 Certificate 消息，携带服务端证书链——通常是站点证书加中间 CA 证书，根证书一般不在链里，客户端本地信任库里有。

抓包看证书重点看几个字段：Subject 里的 CN 或 SAN 是否匹配访问的域名（现代浏览器只认 SAN，CN 已废弃）；Issuer 是签发 CA；有效期起止时间；公钥算法和长度；扩展里的 Key Usage 和 Extended Key Usage 限定这张证书能干什么；最关键的签名值，它是上一级 CA 用私钥对这张证书内容做的签名，校验链就此建立。

四、密钥交换：抓包里最值得看的一段

TLS 1.2 的 ECDHE 密钥交换在抓包里能看到 ServerKeyExchange 消息：服务端给出椭圆曲线参数、公钥，并用证书私钥对这段参数签名。客户端验证签名确认服务端身份后，生成自己的临时公钥发过去（ClientKeyExchange）。双方各用自己的临时私钥加对方公钥算出同一个共享秘密，再结合两个随机数派生出主密钥和会话密钥。这里的关键是“临时”二字：ECDHE 的私钥每次连接重新生成，用完即弃，所以叫前向保密——即使服务端长期私钥泄露，历史流量也解不开。TLS 1.3 直接把密钥交换放进扩展字段，抓包结构变了但原理相同。

五、证书校验：客户端在后台做了什么

抓包只能看到证书传输，校验逻辑在客户端内部。完整校验链包括：验证签名链从站点证书逐级到受信任根，检查每级签发者是否合法；检查有效期；检查域名匹配；检查吊销状态（CRL 或 OCSP）；检查证书用途扩展是否允许当前场景。任何一环失败，浏览器就报证书错误。抓包里常见的握手失败，很多是证书链不完整——服务端只发了站点证书没发中间证书，客户端补不齐链就断。排查时看 Certificate 消息里到底发了几张证书即可定位。

六、加密传输与抓包能看到的边界

握手完成后，ChangeCipherSpec 通知后续消息加密，Finished 消息是第一条加密消息，用于验证握手过程未被篡改。之后的应用数据在抓包里显示为 Encrypted Application Data，看不到内容，只能看到长度和时间。即使解密，看到的也是 HTTP 明文，TLS 本身不改变应用层协议。抓包里能观察的元信息仍有价值：握手耗时、证书大小、加密记录的长度分布、连接复用情况，这些是性能和安全排查的入口。

七、实战排障清单

抓包排障按顺序看：TCP 是否建连成功，排除网络问题；ClientHello 是否发出、SNI 是否正确；ServerHello 选的套件是否双方支持；证书链是否完整、域名是否匹配、有效期是否正常；密钥交换消息是否完整；Finished 是否通过。客户端报错信息配合抓包，基本能定位到是协议版本不匹配、套件不支持、证书问题还是中间设备干扰。记住一条：明文握手阶段是排查主战场，密文阶段只能看流量特征。

TLS 的设计精髓在于用非对称加密解决身份认证和密钥协商，用对称加密解决传输效率，用证书链解决信任传递。抓包把这三层从抽象变成可见的字节，看懂一次完整握手，HTTPS 就不再是黑盒。
